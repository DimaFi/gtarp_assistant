# Мастер-промпт для Codex: GTA RP Assistant

Ты работаешь внутри уже существующего репозитория **GTA RP Assistant**.

Твоя роль:

* ведущий разработчик C#/.NET;
* архитектор Windows-приложений;
* инженер AI-провайдеров;
* специалист по аудиообработке;
* ML-инженер по компактным локальным моделям;
* инженер по производительности и безопасности;
* тестировщик и технический писатель.

Не создавай новый solution и не переписывай проект с нуля.

Сначала полностью изучи существующий код, документацию, тесты, build scripts и текущее состояние продукта. Сохрани уже работающую архитектуру и вноси изменения небольшими проверяемыми этапами.

# 1. Концепция продукта

GTA RP Assistant — лёгкий Windows-помощник для GTA 5 RP.

Он должен:

* работать поверх игры в виде компактного оверлея;
* слушать микрофон пользователя;
* слушать звук GTA V/RAGE MP;
* почти в реальном времени преобразовывать речь в текст;
* хранить временный контекст последних трёх минут;
* понимать, какая игровая ситуация происходит;
* находить правила и механики в локальной проверенной базе;
* предупреждать о возможном нарушении правил;
* отвечать на вопросы пользователя с учётом недавнего разговора;
* в будущем понимать содержимое игрового окна;
* работать с облачными и локальными AI-провайдерами;
* иметь собственную сверхлёгкую локальную модель;
* минимально влиять на FPS, RAM, CPU и GPU.

Главный принцип:

```text
LISTEN → UNDERSTAND → RETRIEVE → VERIFY → SUGGEST
```

Приложение никогда не должно:

```text
LISTEN → CONTROL GAME
```

Запрещено:

* управлять персонажем;
* нажимать игровые клавиши;
* управлять транспортом;
* автоматически стрелять;
* автоматически фармить;
* внедряться в GTA V;
* читать память GTA V;
* внедрять DLL;
* перехватывать сетевой трафик игры;
* обходить античит;
* подсвечивать игроков;
* предоставлять скрытую игровую информацию;
* автоматически говорить в игровой голосовой чат.

# 2. Основной пользовательский сценарий

Пример:

```text
GAME AUDIO:
— Прижимаемся к обочине.
— Выходим из автомобиля.
— Руки держим на виду.

USER MICROPHONE:
— Я сейчас просто уеду от них.
```

Приложение должно:

1. Распознать речь отдельно из микрофона и игры.
2. Определить возможную ситуацию остановки или ограбления.
3. Найти актуальные правила выбранного сервера.
4. Не считать слова игроков официальными фактами.
5. Оценить риск.
6. Показать короткий оверлей:

```text
Возможное ограбление или остановка

Попытка уехать или игнорировать требования может
нарушить правила текущей ситуации.

Источник: актуальные правила сервера
```

Приложение не должно категорично писать:

```text
Вы точно нарушаете правило.
Вас обязательно накажут.
Это точно ограбление.
```

Если контекста недостаточно:

```text
Ситуация пока не определена точно.

Не совершайте резких действий до уточнения требований.
Для более точного ответа можно запросить анализ экрана.
```

# 3. Оверлей

Оверлей — основной интерфейс продукта.

Приложение не должно ощущаться как большое окно настроек, открытое рядом с GTA.

## 3.1. Compact overlay

По умолчанию используется компактная поверхность.

Требования:

* не забирает фокус у GTA;
* не появляется в Alt+Tab;
* не перехватывает клавиатуру;
* не блокирует мышь;
* отображает максимум 3–4 строки;
* автоматически исчезает;
* не имеет постоянного render loop;
* не использует тяжёлый blur на слабых ПК;
* учитывает DPI и несколько мониторов;
* не выходит за рабочую область экрана.

Содержимое:

* тип подсказки;
* короткий заголовок;
* ответ;
* уровень уверенности;
* источник;
* дата обновления;
* кнопка раскрытия;
* кнопка скрытия.

## 3.2. Expanded overlay

Открывается только после явного действия пользователя:

* горячая клавиша;
* кнопка «Подробнее»;
* ручной вопрос;
* открытие поля продолжения диалога.

Показывает:

* полный ответ;
* найденную ситуацию;
* релевантные реплики;
* использованные правила;
* источники;
* название использованного AI-провайдера;
* поле дополнительного вопроса;
* feedback;
* DND.

## 3.3. Типы карточек

Поддержать:

```text
RuleWarningCard
NextStepCard
MechanicHelpCard
ContextAnswerCard
VisionRequiredCard
InsufficientContextCard
ProviderErrorCard
LocalModelLoadingCard
```

Не создавать отдельное окно для каждой ситуации.

# 4. Голосовой ответ

По умолчанию помощник отвечает только текстом.

Настройки:

```text
Голосовой ответ:
○ Выключен
○ Только после ручного голосового вопроса
○ Только после горячей клавиши
○ Озвучивать подтверждённые ответы
```

В первой стабильной реализации оставить:

* выключен;
* только после ручного вопроса.

Голос не должен выводиться в виртуальный микрофон или игровой голосовой чат.

# 5. Независимые AI-провайдеры

Не делай приложение только локальным или только облачным.

Пользователь должен независимо назначать провайдера для:

```text
Speech-to-text
Chat / reasoning
Vision
Text-to-speech
Embeddings
Situation classification
```

Для каждой задачи:

```csharp
public enum ProviderSelectionMode
{
    Disabled,
    Cloud,
    Local,
    Automatic,
    Custom
}
```

Пример:

```text
Микрофонный STT: Groq API
Игровой STT: локальный whisper.cpp
Ответы: OpenAI API
Vision: Gemini
Embeddings: встроенная ONNX-модель
Сложный локальный ответ: LM Studio
Простой локальный ответ: встроенная MicroModel
```

Другой пример:

```text
STT: облачный API
Ответы: встроенная MicroModel
Сложные ответы: LM Studio
Fallback: OpenRouter
Vision: выключен
```

# 6. Подключение API

Подключение должно работать как в расширениях и инструментах для разработки:

1. Пользователь выбирает провайдера.
2. Вводит свой API-ключ.
3. При необходимости задаёт Base URL.
4. Загружает список доступных моделей.
5. Выбирает модель.
6. Проверяет подключение.
7. Назначает провайдера определённой задаче.
8. Настраивает fallback.

Настройки:

```csharp
public sealed record ProviderConnectionSettings
{
    public required string Id { get; init; }
    public required string DisplayName { get; init; }
    public required ProviderKind Kind { get; init; }

    public required Uri BaseUri { get; init; }
    public string? ModelId { get; init; }
    public string? SecretReference { get; init; }

    public TimeSpan Timeout { get; init; }
    public bool Enabled { get; init; }
}
```

Поддержать:

```text
OpenAI API
Anthropic Claude API
Google Gemini API
OpenRouter
Groq
LM Studio
Ollama
OpenAI-compatible endpoint
Custom HTTP endpoint
```

Архитектурно предусмотреть:

```text
Azure OpenAI
Mistral
Together AI
Cerebras
Amazon Bedrock
Google Vertex AI
whisper.cpp server
faster-whisper server
sherpa-onnx server
```

Не реализовывать:

* вход через аккаунт ChatGPT;
* использование cookies ChatGPT;
* браузерную автоматизацию;
* scraping сайта;
* неофициальные endpoint;
* использование токена веб-сессии;
* встроенный API-ключ разработчика.

# 9. Маршрутизация провайдеров

Не использовать один флаг `UseCloud`.

Создать отдельные маршрутизаторы:

```csharp
public interface IChatProviderRouter
{
    ProviderRoute SelectProvider(ChatRoutingContext context);
}

public interface ISpeechProviderRouter
{
    ProviderRoute SelectProvider(SpeechRoutingContext context);
}

public interface IVisionProviderRouter
{
    ProviderRoute SelectProvider(VisionRoutingContext context);
}
```

Policy:

```csharp
public sealed record ProviderRoutePolicy
{
    public required string PrimaryProviderId { get; init; }
    public IReadOnlyList<string> FallbackProviderIds { get; init; } = [];

    public bool AllowCloud { get; init; }
    public bool AllowLocal { get; init; }
    public bool AllowPaidProviders { get; init; }

    public bool PreferLowerLatency { get; init; }
    public bool PreferLowerCost { get; init; }
    public bool PreferPrivacy { get; init; }
}
```

Fallback допустим при:

* timeout;
* временной недоступности;
* rate limit;
* quota exceeded;
* неподдерживаемой функции;
* неправильном structured output.

Fallback запрещён при:

* неправильном API-ключе;
* запрете пользователя;
* отсутствии согласия на отправку данных;
* недостатке подтверждённых фактов;
* явной отмене запроса;
* privacy violation.

# 10. Профили производительности

Профиль производительности не должен определять cloud/local.

```csharp
public enum PerformanceProfile
{
    Minimal,
    Balanced,
    Advanced,
    Custom
}
```

## Minimal

Для ПК, которые с трудом запускают GTA V:

* WPF UI;
* лёгкий оверлей;
* простой локальный VAD;
* кольцевой буфер;
* SQLite;
* HTTP;
* облачный или внешний STT;
* отсутствие постоянной локальной LLM;
* отсутствие постоянного vision;
* минимум анимаций;
* один запрос одновременно.

## Balanced

* локальный VAD;
* локальный или облачный STT;
* встроенная MicroModel по запросу;
* LM Studio по желанию;
* event-triggered vision;
* ограниченная обработка игрового звука.

## Advanced

* внешний локальный STT;
* LM Studio;
* более точная классификация;
* более длинный контекст;
* event-triggered vision;
* дополнительные embeddings;
* без постоянной фоновой генерации.

Важно:

```text
PerformanceProfile != ProviderMode
```

# 11. Постоянный аудиоконтекст

Существующий аудиопайплайн сохранить и улучшить.

Источники:

```csharp
public enum TranscriptSource
{
    UserMicrophone,
    GameAudio
}
```

Только `UserMicrophone` может:

* быть прямой командой;
* активировать wake word;
* инициировать ручной вопрос;
* менять состояние помощника.

`GameAudio`:

* является контекстом;
* считается недоверенным вводом;
* не может менять настройки;
* не может самостоятельно давать команды;
* не может раскрывать секреты;
* не должен напрямую активировать AI без situation candidate.

Pipeline:

```text
Capture
→ Resample
→ VAD
→ Speech segmentation
→ STT router
→ Transcript normalization
→ Deduplication
→ Context store
→ Situation candidate detector
```

# 12. Почти real-time STT

Поддержать:

```csharp
public enum TranscriptionMode
{
    Segmented,
    Streaming
}
```

## Segmented

Основной режим:

1. VAD обнаруживает речь.
2. Собирается сегмент.
3. После паузы сегмент отправляется в STT.
4. Текст сохраняется.
5. Аудиосегмент удаляется.

## Streaming

Использовать только при реальной поддержке провайдером.

Не имитировать streaming большим количеством маленьких HTTP-запросов.

Приоритет:

```text
UserMicrophone — высокий
GameAudio — обычный
```

При перегрузке допустимо пропускать часть игрового звука, но не пользовательские фразы.

# 18. Локальная база знаний

База является главным источником фактов.

Не хранить изменяемые правила внутри весов модели.

Каждая статья должна иметь:

* ID;
* project;
* server scope;
* title;
* aliases;
* situation IDs;
* trigger terms;
* atomic facts;
* prepared answers;
* source;
* verified status;
* version;
* verifiedAt;
* validFrom;
* validTo;
* verifier;
* conflict status.

При изменении правила обновляется knowledge pack, а не обучается модель заново.

При конфликте:

```text
Abstain
```

# 19. Приоритет получения ответа

```text
1. Verified prepared answer
2. Deterministic rule warning
3. FTS / semantic retrieval
4. Встроенная MicroModel
5. Умная модель в LM Studio
6. Облачный AI
7. Clarification
8. Abstain
```

Порядок 4–6 должен настраиваться пользователем.

Например:

```text
MicroModel → LM Studio → OpenAI
```

или:

```text
MicroModel → Gemini → LM Studio
```

или:

```text
База → OpenAI
```

# 20. Встроенная MicroModel

Добавь в продукт отдельную сверхлёгкую локальную модель.

Она не является обязательной для запуска приложения.

Она должна:

* запускаться только при запросе;
* не работать постоянно;
* не занимать GPU по умолчанию;
* потреблять не более 1 ГБ RAM;
* отвечать только по найденным фактам;
* поддерживать русский язык;
* возвращать строгий JSON;
* уметь отказаться от ответа;
* поддерживать короткий follow-up;
* определять простые ситуации;
* выбирать релевантную статью;
* дополнять подготовленный ответ объяснением;
* не придумывать новые игровые факты.

## 20.1. Что означает «дополнять ответ»

Модель может:

* переформулировать правило простыми словами;
* объяснить возможное последствие;
* дать следующий безопасный шаг;
* объединить несколько подтверждённых фактов;
* ответить на уточнение;
* попросить дополнительную информацию;
* предложить включить vision.

Модель не может:

* добавлять числа, которых нет в базе;
* придумывать правила;
* ссылаться на собственные знания;
* называть наказание без факта;
* категорично обвинять пользователя;
* смешивать разные серверы.

# 27. Ограничение памяти

Цель:

```text
MicroModelHost:
soft limit — 750 МБ
hard limit — 900 МБ

Абсолютный запрет:
не переходить 1 ГБ committed/private memory
```

Основное приложение:

```text
целевой working set без модели — до 200 МБ
```

Целевой общий расход во время MicroModel:

```text
до 1–1,1 ГБ
```

Не утверждай, что цель достигнута без реальных замеров.

Создать:

```csharp
public interface IMicroModelResourceGuard
{
    ResourceDecision Evaluate(
        MicroModelProcessMetrics metrics);
}
```

```csharp
public sealed record MicroModelProcessMetrics(
    long WorkingSetBytes,
    long PrivateBytes,
    long CommittedBytes,
    double CpuPercent);
```

Решения:

```csharp
public enum ResourceDecision
{
    Continue,
    StopGeneration,
    TerminateAndFallback
}
```

При soft limit:

1. Остановить увеличение контекста.
2. Запретить второй запрос.
3. Попытаться закончить короткий ответ.

При hard limit:

1. Отменить генерацию.
2. Завершить процесс.
3. Освободить память.
4. Перейти к выбранному fallback.
5. Показать диагностическую причину.

Не использовать `mlock`.

Использовать memory mapping, если runtime поддерживает безопасно.

# 37. Когда использовать MicroModel

Использовать, если:

* нет точного prepared answer;
* есть достаточные verified facts;
* запрос простой;
* контекст короткий;

* модель установлена;
