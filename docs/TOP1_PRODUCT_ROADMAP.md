# План развития GTA RP Assistant до помощника №1

Актуально на 3 августа 2026 года.

Статус: стратегический план. Завершённые функции перечислены в `DEVELOPMENT_CHECKPOINT.md`; этот документ описывает только будущую работу и критерии, по которым её можно считать успешной.

## 1. Что означает «помощник №1»

Цель — не самое большое количество функций и не самая крупная языковая модель. Лучшим считается помощник, который:

1. чаще остальных даёт правильный и актуальный ответ по GTA5RP;
2. отвечает быстрее, чем игрок успевает искать информацию в Wiki, Discord и таблицах;
3. показывает источник, серверную область и свежесть сведений;
4. удобно работает поверх игры текстом и голосом, не забирая управление;
5. устанавливается и запускается на обычном Windows-ПК без ручной отладки;
6. честно сообщает о нехватке данных вместо выдуманного ответа;
7. не внедряется в игру и не автоматизирует действия игрока.

Главное конкурентное преимущество продукта:

```text
проверенная база GTA5RP
  + быстрый поиск и детерминированные ответы
  + AI только для понимания вопроса и удобной формулировки
  + минималистичный overlay
  + прозрачные источники и безопасный abstain
```

## 2. Метрики верхнего уровня

Эти значения являются целевыми. Они не должны обозначаться как достигнутые до появления измеримого отчёта.

### Качество ответа

- не менее 98% корректных ответов на официальном контрольном наборе;
- не менее 95% корректных ответов на player-confirmed данных;
- не менее 99,5% правильного определения server scope;
- 100% фактических ответов содержат источник и дату/статус актуальности;
- менее 0,5% неподтверждённых чисел или игровых утверждений;
- корректный `abstain` не менее чем в 95% вопросов, на которые в базе нет ответа;
- отдельные тесты опечаток, разговорных названий, транслита и коротких вопросов.

### Скорость и удобство

- prepared/extractive ответ: p95 до 300 мс после готового текста вопроса;
- локальная AI-формулировка: p95 до 3 секунд на рекомендованном профиле;
- голосовой вопрос: полезный результат не позднее 4 секунд после окончания речи;
- не менее 80% частых сценариев выполняются через overlay без открытия главного окна;
- основной ответ начинается с короткого решения, подробности раскрываются по запросу.

### Надёжность и совместимость

- не менее 99,9% сессий без аварийного завершения;
- cold start до 3 секунд на поддерживаемом слабом ПК;
- 100 последовательных startup/shutdown циклов без ошибки перед публичным релизом;
- работа на Windows 10 22H2 и актуальных Windows 11, DPI 100/150/200%, нескольких мониторах;
- portable и установленная версия работают из нестандартного Unicode-пути с пробелами;
- отсутствие постоянного влияния на FPS; тяжёлые функции включаются только явно.

### Актуальность базы

- изменение официального источника обнаруживается не позднее 24 часов;
- публикация изменения происходит только после автоматической проверки и review;
- community-сведения имеют автора/происхождение, дату проверки и явную маркировку;
- популярные вопросы без хорошего ответа автоматически попадают в очередь покрытия без сохранения чувствительного текста.

## 3. Порядок реализации

Автономный путь реализуется последовательностью P0–P10 из
`OFFLINE_ASSISTANT_ARCHITECTURE.md`. Она уточняет технический порядок этапов ниже:
сначала единый voice control plane (основной toggle/preview срез завершён, P0.1b hardening следующий), затем встроенный STT и только после
проверенного offline vertical — дополнительные локальные модели, Vision и
контролируемая память.

### T1 — измеримое качество продукта

Статус: завершён 31 июля 2026 года.

- собрать версионированный gold-набор минимум из 250 реальных вопросов, затем расширить до 500;
- покрыть правила, работы, клубы, достижения, рецепты, медицину, экономику, интерфейс и типичные ошибки ввода;
- для каждого вопроса хранить допустимые fact IDs, server scope, ожидаемый ответ/abstain и максимальную свежесть;
- добавить CLI для прогона полного production pipeline, а не только отдельной модели;
- считать accuracy, citation coverage, wrong-server, unsupported numbers, false answer и false abstain;
- сохранять machine-readable JSON и короткий Markdown-отчёт в artifacts;
- сделать падение критического quality gate блокирующим для релиза.

Критерий завершения: воспроизводимый baseline-отчёт текущей версии и автоматический regression gate.

Результат: создано 528 сценариев (524 blocking), CLI прогоняет реальный coordinator и SQLite retrieval, JSON/Markdown-отчёты сохраняются в artifacts, а нарушение порога блокирует `eng/build.ps1`. Зафиксированный baseline: 100% blocking pass/decision/article/citation, 0 ложных ответов, неподтверждённых чисел и wrong-server ответов. Подробности: `PRODUCT_QUALITY_BENCHMARK.md`.

### T2 — полнота и свежесть знаний

- провести инвентаризацию всей официальной GTA5RP Wiki по категориям;
- внедрить read-only обнаружение новых/изменённых страниц и content hash;
- не публиковать найденное изменение автоматически: сначала extraction, schema validation и review;
- добавить версию механики, дату проверки, серверную область и статус устаревания;
- расширять базу волнами по реальной частоте вопросов, а не копировать всё подряд;
- добавить словарь игровых сокращений, опечаток, транслита и народных названий;
- ввести очередь «нет ответа / слабый ответ» из локальной анонимной обратной связи;
- сохранить отдельное происхождение official и community данных.

Критерий завершения: не менее 90% top-250 вопросов имеют проверенный короткий ответ, источник и тест.

### T3 — лучший поиск и формирование ответа

- реализовать единый query normalizer для опечаток, морфологии, сокращений и транслита;
- объединить exact/prepared, FTS/BM25, aliases и server-aware фильтрацию;
- добавить лёгкий reranker только после измерения baseline;
- отделить фактическое ядро ответа от AI-формулировки;
- выводить ответ слоями: коротко → шаги → условия → источник → подробности;
- добавить детерминированные калькуляторы там, где игроку нужны сравнения, доход, стоимость или время;
- разрешить пользователю сообщить «не тот сервер», «устарело», «не помогло» одним действием;
- превращать каждый подтверждённый дефект ответа в regression test.

Критерий завершения: достижение целевых quality-метрик T1 без ухудшения latency.

### P0.1/M3 — полноценный Push-to-Talk и единый voice control plane

- один `VoiceInteractionCoordinator` владеет жизненным циклом голосового запроса;
- режимы удержания и переключателя;
- визуальный уровень микрофона, тест устройства и понятные ошибки;
- VAD, максимальная длительность и отмена;
- preview распознанного текста или настраиваемая автоотправка;
- выбор локального/cloud STT независимо от Chat;
- единый `SpeechToTextProviderCatalog`, без сборки route в нескольких ViewModel/controller;
- hotkey conflict detection и восстановление после unplug/replug;
- короткий listening/thinking/result UX в overlay.

Критерий завершения: голосовой сценарий полностью проходит без открытия главного окна и не отправляет ошибочно распознанный текст без выбранного пользователем режима.

### P0.2/P0.3 — встроенный STT и полный offline vertical

- optional STT pack устанавливается отдельно от основного ZIP и проверяется по manifest/hash;
- распознавание работает на CPU без LM Studio, Ollama, Python и cloud;
- отсутствие pack не ломает ручной текст и существующий provider fallback;
- путь PTT → STT → preview → knowledge → validation → overlay → Windows TTS проходит на чистом Windows-ПК;
- weak-PC профиль соблюдает resource budget и может отключить optional AI-формулировку.

Критерий завершения: воспроизводимый offline smoke на чистом профиле и измеренные latency/RAM/CPU без скрытого сетевого запроса.

### T4 — контекстный помощник поверх игры

- ручной текстовый ввод в expanded overlay без потери фокуса в compact-режиме;
- отдельные opt-in режимы: вопрос, RP-ситуация, работа, клуб, правило, расчёт;
- временный контекст последних реплик с ограниченным TTL;
- game-audio context только с явным включением и видимым индикатором;
- vision только по ручному запросу и после preview/consent;
- confidence-aware карточки: ответ, предупреждение, нужно уточнение, недостаточно данных;
- никаких нажатий клавиш, управления GTA, чтения памяти или скрытого захвата.

Критерий завершения: частые игровые вопросы решаются за одно действие, при этом overlay не мешает управлению и соблюдает anti-cheat boundaries.

### M4 — документный центр знаний

- список источников, категории, статус, дата обновления и server scope;
- просмотр документа, chunks и фактов;
- точная ссылка из ответа на использованный фрагмент;
- импорт `.txt`, `.md`, `.json` с preview и validation;
- enable/disable, reindex, review queue и rollback версии pack;
- понятная маркировка официальных и player-confirmed сведений.

Критерий завершения: пользователь и редактор могут проверить происхождение любого фактического ответа.

### M5/M6 — контролируемая память и персонализация

- память только после отдельного opt-in;
- кандидаты в память с подтверждением, редактированием и удалением;
- профиль сервера, уровня, клубов и предпочтений с датой подтверждения;
- summaries длинных диалогов и ограниченный `ContextBuilder`;
- запрет считать пользовательскую память официальным игровым фактом;
- экспорт, очистка и локальный просмотр всех сохранённых данных.
- отдельный opt-in адаптивного характера: bounded traits, объяснимые изменения, ручная фиксация и полный сброс;
- характер меняет подачу и инициативность, но не факты, citations, safety и grounded validation.

Критерий завершения: персонализация улучшает релевантность на отдельном eval-наборе и не создаёт скрытого хранения данных.

### T5 — современный модульный дизайн

- завершить дизайн по `docs/design`, сохранив Discord-подобную спокойную плотность;
- унифицировать состояния loading/empty/error/success и типы overlay-карточек;
- добавить компактную командную палитру и быстрые действия;
- использовать blur только как опциональное улучшение с no-blur fallback;
- обеспечить keyboard navigation, screen reader labels, contrast и reduced motion;
- вести visual regression snapshots для всех основных размеров и тем;
- не раздувать shell: каждый новый раздел остаётся отдельным feature module.

Критерий завершения: единый component catalog, отсутствие локальных дублирующихся стилей и успешная аппаратная UI-матрица.

### T6 — модели и локальные движки без зависимости от одного приложения

- сохранить LM Studio как основной проверенный адаптер;
- добавить адаптеры Ollama и прямого llama.cpp только через общий контракт;
- автоматически обнаруживать модели, но менять активную только после capability gate;
- предложить профили «слабый ПК», «сбалансированный», «качество»;
- измерять latency, RAM/VRAM, JSON и grounding на пользовательской модели;
- не включать собственную MicroModel до успешного ADR после dataset/fine-tuning;
- приложение всегда остаётся полезным без модели.

Критерий завершения: смена runtime не меняет Core pipeline и не ломает knowledge-first fallback.

### T7 — релиз уровня массового продукта

- подписанный installer/MSIX без требования администратора там, где это возможно;
- безопасное обновление с manifest, подписью, rollback и сохранением пользовательских данных;
- first-run wizard: аудио, hotkeys, производительность, Local AI и privacy;
- встроенная диагностика с экспортом privacy-safe архива;
- opt-in crash reporting без transcript, скриншотов и API-ключей;
- hardware QA на слабом/среднем/сильном ПК;
- публичные release notes, известные ограничения и воспроизводимые SHA-256.

Критерий завершения: новый пользователь устанавливает приложение, задаёт первый вопрос и получает корректный ответ без чтения технической документации.

### T8 — сообщество и устойчивое преимущество

- публичный формат предложений исправлений и новых community-фактов;
- review workflow и репутация авторов без автоматического доверия;
- кнопка обратной связи с категорией проблемы;
- dashboard покрытия и свежести без публикации приватных пользовательских запросов;
- короткие видео/скриншоты сценариев и понятный GitHub README;
- Discord-канал поддержки и прозрачный changelog;
- ежемесячный benchmark-отчёт качества.

Критерий завершения: улучшения базы приходят из реального использования, проверяются и попадают в релиз быстрее, чем информация успевает устареть.

## 4. Ближайшие пять логических этапов

1. **P0.1:** единый voice interaction control plane, hold/toggle, preview и отмена.
2. **P0.2:** встроенный CPU STT pack с manifest, capability gate и fallback.
3. **P0.3:** полный offline voice knowledge vertical на чистом Windows-профиле.
4. **T2/T3:** первая волна покрытия top-250 вопросов и улучшение поиска.
5. **M4:** document-oriented Knowledge UI и точные citations.

После каждого этапа обязательны профильные тесты, полный `eng/build.ps1`, визуальная проверка изменённых страниц, обновление документации и новая active checkpoint.

## 5. Что не следует делать сейчас

- подключать ещё одну chat-модель до повторного успешного ADR и измеримого resource/quality gate;
- автоматически доверять непроверенному тексту из Discord, таблиц или Wiki extraction;
- пытаться слушать и анализировать всё постоянно по умолчанию;
- добавлять функции, управляющие игрой;
- переписывать работающую архитектуру ради нового UI-фреймворка;
- объединять knowledge, историю диалогов и память пользователя в одну базу;
- обещать «№1» по количеству функций без измерений качества и реальных пользовательских тестов.

## 6. Условие достижения цели

Формулировку «помощник №1» можно использовать как подтверждённый результат только после:

- выполнения целевых quality/reliability/latency метрик;
- внешнего тестирования минимум на трёх классах ПК;
- тестирования реальными игроками разных серверов и ролей;
- публикации воспроизводимого benchmark-отчёта;
- сравнения времени и успешности решения одинаковых задач с ручным поиском в Wiki/Discord.

До этого «№1» остаётся направлением продукта, а не рекламным утверждением.
