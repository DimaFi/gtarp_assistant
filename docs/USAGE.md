# Руководство пользователя GTA RP Assistant

Актуально на 15 августа 2026 года. Эту инструкцию следует обновлять вместе с пользовательскими сценариями, настройками провайдеров и горячими клавишами.

## Голос и история в версии 0.4.1

1. При первом запуске выберите микрофон. Если голосовая активация не выключена, следующие запуски автоматически начинают локально слушать фразу «Лаберти, слушай».
2. Произнесите фразу и вопрос. Пауза 1,1 секунды считается окончанием реплики; если заговорить раньше, новая часть добавится к тому же вопросу.
3. После ответа в течение 12 секунд можно произнести уточнение без повторения имени.
4. Фраза меняется в **Поведение → Голосовая активация**. Режим «Только после фразы активации» не отвечает на обычные разговоры.
5. История сохраняется локально по умолчанию. Диалоги выбираются в списке в шапке страницы **Ассистент**; сохранение отключается в **Приватности**.
6. Встроенный GigaAM v2 STT работает без Windows Speech, LM Studio, Python, сети и отдельного .NET.

## 1. Как запустить приложение

### Готовая portable-сборка

1. Скачайте из GitHub Releases архив `GtaRpAssistant-<версия>-win-x64.zip` и файл с тем же именем и расширением `.sha256`.
2. Сверьте SHA-256 архива с опубликованным значением.
3. Распакуйте архив в обычную пользовательскую папку.
4. Запустите `GtaRpAssistant.App.exe`.

Релиз поддерживает Windows 10/11 x64. Portable-сборка self-contained: установка .NET SDK или .NET Desktop Runtime не требуется. Текущий релиз пока не подписан сертификатом. Если Windows показывает SmartScreen, продолжайте запуск только после проверки источника и SHA-256.

### Текущая локальная сборка проекта

Уже собранное приложение находится здесь:

```text
artifacts\publish\win-x64\GtaRpAssistant.App.exe
```

Его можно запустить из PowerShell:

```powershell
& ".\artifacts\publish\win-x64\GtaRpAssistant.App.exe"
```

Для запуска непосредственно из исходного кода:

```powershell
dotnet run --project src/GtaRpAssistant.App -c Release
```

Установка, обновление и удаление через пользовательские PowerShell-скрипты описаны в [INSTALLATION.md](INSTALLATION.md).

## 2. Самый быстрый сценарий без AI-модели

LM Studio не обязателен.

1. Откройте раздел **Ассистент**.
2. Введите вопрос, например: `Как лечить артериальное кровотечение?`.
3. Нажмите **Получить ответ**.

Приложение выполнит поиск по локальной базе GTA5RP и покажет подготовленный подтверждённый ответ. Если проверенных данных недостаточно, ассистент безопасно откажется от догадки.

## 3. Подключение локального AI

### Автоматическая настройка LM Studio

1. Откройте в GTA RP Assistant раздел **AI и модели**.
2. Если LM Studio ещё нет, нажмите **Установить и настроить**, выберите существующую папку на любом диске и подтвердите установку. Приложение использует официальный headless LM Studio Core (`llmster`), поэтому отдельное большое desktop-окно не требуется.
3. Мастер скачивает сценарий только с `https://lmstudio.ai/install.ps1`, ограничивает его размер, проверяет обязательные trust-маркеры и запускает без окна. Официальный сценарий дополнительно проверяет SHA-512 скачанного runtime.
4. После установки приложение сохраняет точный путь к `lms.exe` и автоматически продолжает: API → подбор профиля → скачивание → загрузка → память → capability-test → сохранение.
5. Если LM Studio/LM Studio Core уже установлен, сразу нажмите **Настроить автоматически**.

Модель может занимать несколько гигабайт на диске; установка движка и скачивание модели начинаются только после явного действия и подтверждения. Процесс можно остановить кнопкой **Отменить**. Кнопка **Освободить память** выгружает модель из RAM/VRAM, но не удаляет файл.

Если автоматический запуск сообщает об ошибке `llmster`, один раз откройте LM Studio и затем нажмите **Запустить API**. Ассистент повторит штатный `lms server start` через desktop backend. Если daemon продолжает завершаться timeout или desktop сразу закрывается, обновите/переустановите LM Studio либо установите актуальный headless daemon; локальная база GTA RP Assistant продолжит работать без него.

### Использование уже установленной модели LM Studio

1. В LM Studio заранее скачайте любую подходящую instruct/chat-модель.
2. В GTA RP Assistant откройте **AI и модели** и нажмите **Обновить состояние**.
3. В списке **Установленная chat-модель** выберите нужную модель. Embedding-модели в этот список не попадают.
4. Нажмите **Использовать выбранную**.
5. Ассистент загрузит модель с выбранным профилем, проведёт capability-test и только после успешной проверки сохранит её как Local Chat route.

Если проверка не пройдена, предыдущий рабочий маршрут не изменяется. Для фактической загрузки и предварительной оценки используются одинаковые параметры: выбранный context, одна параллельная генерация, GPU-профиль и TTL. Сбалансированный профиль использует CPU-first загрузку: это предотвращает зависание при запущенных GTA/OBS и занятой VRAM. Профиль **Качество** оставляет автоматическое GPU-размещение LM Studio.

### Подключение собственного GGUF-файла или папки

1. Нажмите **Выбрать GGUF-файл**, чтобы указать один файл, либо **Найти GGUF в папке**, чтобы просканировать выбранный каталог.
2. При поиске в папке выберите один найденный файл; приложение не импортирует несколько моделей без отдельного выбора.
3. Ассистент проверит расширение, заголовок `GGUF` и отклонит `mmproj`, повреждённые и неподдерживаемые sharded-файлы.
4. LM Studio сначала выполняет безопасный dry-run, затем копирует модель в своё управляемое хранилище. Исходный файл не перемещается и не удаляется.
5. После импорта модель появляется в списке, загружается и проходит тот же capability-test.

Импорт использует локальное имя репозитория `local-imports/<безопасное-имя>` и не требует соединения с Hugging Face. Папку хранения моделей выбирайте в настройках самой LM Studio; GTA RP Assistant не меняет её скрытно.

### Ручная и расширенная настройка

1. Включите **Расширенные настройки**.
2. Если LM Studio установлена нестандартно, кнопкой **Обзор…** укажите полный путь к `lms.exe` и/или `LM Studio.exe`. Пустое поле включает автоматический поиск; кнопка **Вернуть автоматический поиск** очищает оба ручных пути.
3. Укажите loopback endpoint, обычно `http://127.0.0.1:1234/v1`.
4. Нажмите **Получить модели**, выберите точный **Chat Model ID** и назначьте маршруту **Chat / reasoning** режим **Local**. Для установленной модели удобнее использовать список и кнопку **Использовать выбранную** выше.
5. Необязательно укажите отдельный **Embedding Model ID** и включите для Embeddings режим **Local**. Эта модель используется только при неоднозначном поиске, не запускается во время GTA и не заменяет chat-модель. Пустое поле оставляет быстрый SQLite-only режим.
6. Выберите профиль **Компактный**, **Сбалансированный** или **Качество**.
7. Выполните **Capability-test**, затем **Сохранить и применить**.

Типичные пути: `%UserProfile%\.lmstudio\bin\lms.exe` для CLI и выбранная при установке папка `LM Studio.exe` для desktop-приложения. Можно использовать другой диск и папки с пробелами. Путь к GTA указывать не требуется: монитор находит запущенную игру по процессу независимо от папки Steam, Epic Games или Rockstar Launcher.

Этим способом можно подключить уже запущенный OpenAI-compatible `llama-server`. Автоматические download/load/unload сейчас реализованы только для LM Studio.

API key для обычного локального LM Studio чаще всего не требуется. Если ваш сервер требует ключ, он хранится через Windows DPAPI и не записывается в `settings.json`.

Обычные данные находятся в `%LocalAppData%\GtaRpAssistant`. Для portable/тестового профиля каталог можно переопределить переменной среды `GTA_RP_ASSISTANT_DATA_DIR`; настройки и база будут созданы в ней.

### Что означает результат capability-test

- **Подходит** — модель прошла все обязательные проверки теста.
- **Использовать с предупреждением** — endpoint отвечает, но одна или несколько проверок качества провалены.
- **Модель недоступна** — сервер остановлен, выбран неправильный Model ID либо модель не загружена.

Capability-test оценивает совместимость, но не гарантирует качество на всех вопросах. Ответы модели всё равно проходят локальный grounded validator.

## 4. Использование во время игры

### Текстовый чат и диалоги

- Введите вопрос и нажмите **Отправить** или `Enter`.
- `Shift+Enter` добавляет перенос строки без отправки.
- В верхней панели находятся предыдущие диалоги. Кнопка **＋ Новый чат** создаёт новый.
- Название создаётся автоматически по смыслу первого содержательного вопроса. Выберите диалог, измените соседнее поле и нажмите **Переименовать**, если хотите своё название.
- **Удалить** требует подтверждения и удаляет весь выбранный диалог без восстановления.
- **Повторить** снова отправляет последний вопрос, **Копировать ответ** помещает последний ответ в буфер, **Отмена** останавливает активную обработку.

По умолчанию список существует только в текущем запуске. Для продолжения после перезапуска откройте **Приватность → История общения**, включите **Долгосрочное общение** и сохраните настройки. Сообщения будут храниться локально в `%LocalAppData%\GtaRpAssistant\assistant-data.db`.

Ответы поддерживают безопасное отображение заголовков, списков, жирного текста и inline-code. HTML не выполняется, ссылки модели не открываются автоматически.

### Оверлей и горячие клавиши

- `Ctrl+Alt+Q` — показать или скрыть оверлей.
- `Ctrl+Alt+A` — начать ручной голосовой вопрос. В режиме toggle повторное нажатие отменяет запрос; в режиме hold говорите, пока удерживаете сочетание.
- `Ctrl+Alt+S` — сделать снимок окна GTA с обязательным предварительным просмотром.
- `Ctrl+Alt+P` — полностью поставить ассистента на паузу или возобновить его.

Compact overlay не должен забирать фокус у GTA. Его можно перетащить мышкой в любое место экрана; позиция сохраняется и ограничивается рабочей областью монитора. В разделе **Поведение** overlay можно полностью скрыть или закрепить. Для полного ответа его можно раскрыть вручную; `Esc` закрывает expanded-панель.

После `Ctrl+Alt+A` поверх игры появляется зелёно-белый пульсирующий индикатор **Слушаю**. Рядом печатается распознанный вопрос, чтобы его можно было проверить. После распознавания открывается редактируемый предпросмотр: исправьте текст и нажмите **Отправить** либо отмените запрос. Во время подготовки и показа ответа индикатор становится сине-белым, а текст ответа дублируется рядом. До подтверждения вопрос не уходит в answer pipeline. Если в разделе **Аудио** явно включить **Сразу отправлять распознанный голосовой вопрос**, подтверждение пропускается; по умолчанию эта настройка выключена.

В разделе **Аудио → Режим Ctrl+Alt+A** доступны два варианта. Toggle удобнее по умолчанию: одно нажатие начинает запись, второе отменяет. Hold завершает текущий речевой сегмент сразу после отпускания клавиш. Измените режим и нажмите **Сохранить настройки** — перезапуск не требуется.

После закрытия основного окна приложение продолжает работать в системном трее. Через меню трея его можно открыть, поставить на паузу или полностью завершить.

На странице **Поведение** можно выбрать светлую или серую тему и нажать **Сохранить настройки**. Тема применяется ко всему окну через общие токены дизайн-системы и сохраняется между запусками.

## 5. Микрофон и звук игры

1. В разделе **Аудио** нажмите **Обновить устройства**.
2. Выберите микрофон.
3. Нажмите **Тест микрофона** и в течение трёх секунд говорите обычным голосом. Индикатор должен реагировать, а рядом появится результат теста.
4. При необходимости выберите устройство, через которое слышен звук GTA.
5. Оставьте **Сразу отправлять распознанный голосовой вопрос** выключенным, если хотите проверять и редактировать текст перед отправкой.
6. Нажмите кнопку запуска прослушивания и сохраните настройки.

Для автономного распознавания установите отдельный проверенный STT-пак и на странице **Аудио** оставьте включённой галочку **Использовать автономный STT-пак при наличии**. Пак ищется сначала по выбранному пути, затем рядом с приложением в `model-packs\stt`, затем в `%LOCALAPPDATA%\GtaRpAssistant\model-packs\stt`. Нестандартную папку можно выбрать кнопкой **Выбрать…**. Текущая локальная сборка в `artifacts\publish\win-x64` уже содержит adjacent-пак для ручной проверки; публичный ZIP не содержит веса до успешного русского comparative quality gate. Без пака можно настроить отдельный OpenAI-compatible endpoint с маршрутом `audio/transcriptions`. Наличие chat-модели в LM Studio само по себе не означает поддержку распознавания речи. Без любого STT полностью работает ручной текстовый ввод.

Звук игры используется только как временный контекст и сам по себе не запускает подсказку. Включать его необязательно.

## 6. Vision и голосовой ответ

Vision выключен по умолчанию. Чтобы включить его:

1. Откройте раздел **Приватность**.
2. Разрешите ручной vision после preview.
3. Укажите vision-модель, которую действительно поддерживает выбранный endpoint.
4. Сохраните настройки.

После `Ctrl+Alt+S` снимок сначала показывается пользователю. Отправка выполняется только после подтверждения. Приложение не сохраняет снимок на диск.

Кнопка **Фото** в поле вопроса позволяет выбрать PNG/JPEG до 12 МБ. Файл декодируется с ограничением 33 Мп, преобразуется во временный PNG и показывается в том же preview. Сначала запускается локальный OCR: если он уверенно прочитал интерфейс, тяжёлая модель не загружается. Иначе используется только локальный Vision provider. Для вложений облачный fallback намеренно запрещён; исходные и преобразованные байты очищаются после обработки.

В карточке подтверждения отдельно показано назначение — endpoint/provider, который получит кадр. `Enter` подтверждает отправку, `Esc` или кнопка **Отмена** закрывает окно без анализа. В provider уходит только показанный кадр; после завершения он удаляется из памяти.

Для голосового ответа выберите в **Приватности** режим **Только после Ctrl+Alt+A**, системный голос Windows и устройство вывода. TTS не включается для фонового game audio.

## 7. Основные настройки

- **Поведение → Сервер** — scope базы знаний GTA5RP; при сомнении оставьте `all`.
- **Поведение → Следить за GTA** — автоматически отслеживать запуск и перезапуск игры.
- **Поведение → Оверлей** — положение и время показа.
- **Поведение → Проактивность** — `Off`, `Strict`, `Balanced` или экспериментальный режим.
- **Приватность → Очистить временный контекст** — немедленно удалить transcript/audio-контекст из памяти.
- **Приватность → Долгосрочное общение** — сохранять диалоги локально между запусками; по умолчанию выключено.
- **AI и модели → Разрешить облачные маршруты** — явное разрешение cloud fallback; по умолчанию оно выключено.

Настройки и логи находятся в `%LocalAppData%\GtaRpAssistant`. Аудиофайлы и снимки приложение на диск не записывает. Отправленный пользователем текст сохраняется как сообщение только при включённом долгосрочном общении.

## 8. Типичные проблемы

### «Невозможно соединиться с удалённым сервером»

- запустите API server в LM Studio или `llama-server`;
- проверьте порт и окончание `/v1`;
- убедитесь, что используется `127.0.0.1` или `localhost`;
- нажмите **Получить модели** повторно.

### «Указанная модель отсутствует»

- загрузите модель в runtime;
- получите список моделей заново;
- выберите точный Model ID и сохраните настройки.

### LM Studio установлена или модели лежат не в стандартной папке

- в расширенных настройках укажите полный путь к `lms.exe` и `LM Studio.exe`;
- для возврата к обычному обнаружению нажмите **Вернуть автоматический поиск**;
- папка с весами настраивается в LM Studio, после чего нажмите **Обновить состояние**;
- если у вас отдельный GGUF вне хранилища LM Studio, используйте **Выбрать GGUF-файл** или **Найти GGUF в папке**.

### Текстовый поиск работает, а микрофон — нет

Chat и STT являются разными задачами. Сначала обновите список устройств и выполните **Тест микрофона**. Затем установите/выберите embedded STT-пак, настройте совместимый внешний STT endpoint либо используйте ручной ввод. Старое ошибочное назначение Qwen/LM Studio как `whisper-1` удаляется автоматически миграцией настроек. При неожиданном отключении приложение отменяет текущий voice request и примерно 20 секунд ожидает возвращения того же выбранного микрофона. Оно не переключается скрытно на другое устройство. Если восстановление не произошло, подключите микрофон и нажмите **Обновить устройства**.

### Горячая клавиша не работает

Приложение сообщает, какая именно команда конфликтует. Закройте программу, занявшую сочетание, либо выберите hold-режим для голосового вопроса и сохраните настройки. Все функции также доступны из основного окна или трея.

### Ассистент отказывается отвечать

Это ожидаемое безопасное поведение, если в базе нет подтверждённых данных, сведения конфликтуют, относятся к другому серверу или модель вернула непроверенный ответ. Уточните вопрос и сервер.

### Оверлей не виден поверх GTA

- проверьте, не включена ли полная пауза;
- попробуйте borderless/windowed режим вместо exclusive fullscreen;
- смените позицию оверлея в разделе **Поведение**;
- проверьте `Ctrl+Alt+Q`.

## 9. Текущие ограничения

- История диалогов и управление ими подключены; семантические воспоминания, профиль пользователя и автоматические summaries ещё не реализованы.
- Встроенная GGUF-модель намеренно не поставляется; основной локальный AI — внешний LM Studio или OpenAI-compatible `llama-server`.
- Безопасное удаление файла модели из интерфейса пока недоступно: модель можно выгрузить из памяти, а файл удалить средствами LM Studio.
- Автоподбор учитывает доступную RAM и backend estimate, но не заменяет реальный capability/performance test на конкретном ПК.
- Автообновление, подписанный installer и MSIX ещё не подготовлены.

## 10. Проверка Local AI для разработчика

Автоматический двухпроцессный UI E2E проверяет обнаружение установленной chat-модели, отсутствие embedding-моделей в списке, capability-test и восстановление выбора после перезапуска:

```powershell
.\eng\local-ai-e2e.ps1
```

Отчёты сохраняются в `artifacts/local-ai-e2e/<дата-время>`. Полная релизная проверка выполняется командой:

```powershell
.\eng\build.ps1 -Configuration Release -Runtime win-x64 -SoakIterations 10
```

Техническое состояние следующего этапа описано в [LOCAL_AI_QUALITY_AND_CONVERSATION_PLAN.md](LOCAL_AI_QUALITY_AND_CONVERSATION_PLAN.md).
