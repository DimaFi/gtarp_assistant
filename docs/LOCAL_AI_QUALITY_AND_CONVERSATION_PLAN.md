# Local AI Quality and Conversation Milestone

Актуально на 18 июля 2026 года.

## Цель

Основной локальный AI подключается как внешний runtime. Сейчас полностью поддерживается LM Studio; архитектура `ILocalAiEngineAdapter` допускает последующее добавление Ollama, llama.cpp и других OpenAI-compatible движков. Приложение сохраняет полноценный knowledge-first режим без модели за счёт prepared answers, локального поиска и безопасного abstain.

## Что завершено

### Управление Local AI

- Страница «AI и модели» при открытии приложения проверяет LM Studio, CLI, локальный API, скачанные и загруженные модели.
- Кнопка «Настроить автоматически» выполняет мастер: discovery → запуск llmster/API → подбор модели → оценка памяти → скачивание → загрузка → capability-test → сохранение профиля.
- Доступны отдельные действия «Скачать», «Загрузить в память», «Освободить память», «Оценить нагрузку», «Проверить» и «Отменить».
- Реализован каталог Qwen3 4B Instruct 2507, Granite 4 Micro и Qwen3-VL 4B с назначением, RAM/VRAM и capability metadata.
- Для локальных запросов применяются профильный лимит ответа и TTL; одновременно coordinator обрабатывает один запрос.
- CLI-команды имеют timeout, cancellation и принудительное завершение дерева процессов. Перед запуском HTTP API отдельно проверяется и запускается headless-daemon `llmster`.
- Нестандартная установка LM Studio обнаруживается через CLI и Windows registry; пользователь может явно выбрать `lms.exe` и `LM Studio.exe`, а затем вернуть автоматический поиск.
- При зависании CLI запуск ограничен timeout, всё дерево процесса завершается, после чего приложение пробует безопасный desktop fallback, явно выполняет `lms server start` и показывает конкретную диагностику.
- Пользователь может выбрать любую установленную instruct/chat-модель LM Studio. Выбор сохраняется между запусками, а embedding-модели отфильтровываются.
- Собственный GGUF можно выбрать напрямую или найти в явно выбранной папке. Перед импортом проверяются формат и сигнатура; LM Studio выполняет offline dry-run с локальным `--user-repo`, затем копирует файл через `--copy` без перемещения оригинала.
- Оценка и реальная загрузка используют единый профиль: context, одна параллельная генерация, GPU policy и TTL. Для `auto` параметр GPU не навязывается LM Studio.
- Расширенные endpoint, route и API-key настройки скрыты в простом режиме. Ключи остаются в DPAPI, cloud — только после явного разрешения.

### Conversation и grounded problem solving

- Ограниченная история диалога подключена к `AssistantSessionCoordinator`; она очищается по TTL, смене ситуации и кнопке «Новый диалог».
- Классифицируются direct, follow-up, current situation, rule risk, problem solving и vision requests.
- Follow-up получает только короткую релевантную историю и проверенные факты.
- Validator проверяет обязательные поля, fact IDs, server scope, числа, URL и запрещённую автоматизацию во всех пользовательских строках.
- Поддерживаются `summary`, `steps`, `possibleCauses`, запрос уточнения, visual context и follow-up suggestions.
- Невалидный ответ ремонтируется один раз у того же провайдера, затем pipeline переходит к следующему разрешённому fallback. Ошибки авторизации не обходятся.
- Compact overlay показывает до трёх шагов, expanded overlay — полный план, возможные причины, уточнения, источник и provider/model.

## На каком этапе приложение работает

Приложение уже работает как knowledge-first GTA5RP Assistant без LM Studio: ручной вопрос, локальный поиск, prepared answers, безопасный validator, история текущего диалога и overlay готовы. Реальный путь LM Studio 0.4.19 также подтверждён: приложение обнаруживает runtime, выбирает или импортирует модель, загружает её, проверяет и сохраняет маршрут между запусками. Если runtime не готов или модель не проходит gate, приложение не ломается и остаётся в локальном knowledge/fallback режиме.

## Ограничения

- «Настроить автоматически» может скачать несколько гигабайт; операция запускается только явным нажатием пользователя и отменяется кнопкой «Отменить».
- LM Studio/llmster должен быть исправно установлен и хотя бы один раз инициализирован. Ошибка daemon показывается в приложении и не приводит к бесконечному ожиданию.
- Прогноз памяти является предварительным; окончательное решение принимает capability-test на целевом ПК.
- STT и Vision — независимые routes. Наличие chat-модели не устанавливает Whisper и не включает отправку снимков.
- Встроенный `MicroModelHost` остаётся mock: Qwen3-0.6B и SmolLM2-360M ранее отклонены benchmark gate и не входят в релиз.
