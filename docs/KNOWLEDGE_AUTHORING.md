# Авторство и проверка базы знаний

Реальные игровые правила добавляются только для конкретного сервера и только по официальному источнику. Шаблоны находятся в `knowledge/templates`. До независимой проверки статья и каждый её факт остаются с `verified: false`; приложение не должно выдавать такие данные как подтверждённый ответ.

## Рабочий процесс

1. Автор фиксирует точный ID сервера в `serverScope`, HTTPS-ссылку на официальный источник и дату доступа в `updatedAt`.
2. Одно утверждение оформляется одним атомарным `fact`. Ответы в `preparedAnswers` не должны добавлять чисел, условий или исключений, которых нет в фактах.
3. Автор задаёт `validUntil` — срок следующей проверки. Для часто меняющихся механик срок должен быть короче.
4. Другой человек сверяет каждый факт с источником. После проверки он заполняет `verifiedBy`, переключает статью и все факты в `verified: true`, увеличивает `version` при изменении существующей статьи.
5. Перед включением pack выполняются структурная и governance-проверки:

```powershell
dotnet run --project tools/GtaRpAssistant.KnowledgePackTool -c Release -- validate path/to/pack --strict
dotnet run --project tools/GtaRpAssistant.KnowledgePackTool -c Release -- inspect path/to/pack --json
```

`--strict` считает предупреждения ошибками. Проверенная статья обязана иметь reviewer и абсолютный HTTPS URL. Просроченная статья считается ошибкой. Отсутствующий `validUntil` является предупреждением и блокирует строгую release-проверку.

## Отзыв и обновление

Если источник изменился, правило стало сомнительным или сервер обновил механику, статью немедленно переводят в `verified: false`, а факты — в `verified: false`. После повторной проверки обновляются `updatedAt`, `validUntil`, `verifiedBy` и `version`. Старую формулировку нельзя оставлять подтверждённой «до выяснения».

Demo-pack намеренно не содержит реальных правил. Его нельзя превращать в verified-pack без выбора сервера, официальных источников и reviewer.
